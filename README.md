# PCタイクーン（仮題）— 試作1（段階1・改）

机ひとつでPCを組み始め、人を雇って育てていく、スマホ縦画面の経営シミュレーション（タイクーン×incゲーム）です。
試作1は **段階1（自室）**：開始から所持金 400,000円（貸し倉庫の初期費用）に届くまで。想定の遊び方で約5分です。

**遊ぶ：https://109mei.github.io/pc-tycoon/**

仕様は [docs/SPEC.md](docs/SPEC.md)、数値は [src/data/balance.json](src/data/balance.json)（元は [docs/balance.stage1.json](docs/balance.stage1.json)）、画面の見本は [docs/rough/](docs/rough/)（版1の配置）、実装のスクリーンショットは [docs/screens/](docs/screens/) にあります。

## 遊び方

ジャンクPC →（分解・検品）→ 部品4種類 →（組み立て：1種類ずつ）→ 再生PC →（発送：注文1件）→ 入金

部品はマザーボード・メモリ・ストレージ・電源の4種類です。ジャンクを分解すると種類ごとに検品され、壊れた部品は捨てられます。4種類そろうと1台組めます。

| 操作 | やり方 |
|---|---|
| 作業（分解・組み立て・発送） | 画面下の大きなボタン。タップで1回、長押しで材料がある限り続ける。作業中のタップは1回だけ予約される |
| 画面の切り替え（生産・制作・販売） | 作業ボタンのすぐ上の切り替えバーをタップ、または画面を左右にスワイプ（PCでは ← → キーも使える） |
| 仕入れ | 生産の画面の ×1・×5。「自動」をONにすると、足りなくなったぶんを自動で買う |
| 新品で補う | 制作の画面。組めないとき、足りない部品（2種類まで）を新品で買える |
| 出品価格 | 販売の画面の −／＋。高いと注文が減り、安いと増える。評価（売った件数）が増えると高い値段が選べる |
| 下請け | 販売の画面か「契約」タブで「受ける」。支給キット（1台分の部品一式）で組み立てると1台ごとに報酬、納期を過ぎると違約金 |
| アルバイト | 「社員」タブ。担当の列を選んで雇うと、その列の作業を代わりに続けてくれる（段階1は2人まで） |
| 設定 | 右上の歯車。昼夜の切り替え、セーブの書き出し・読み込み、最初からやり直す |

- 60秒ごとに電気代・家賃・給料を払います。足りないと支払いの表示が赤くなり、払えないと30秒の猶予のあと倒産です。
- 切り替えバーの赤い「！」は、いちばん詰まっている列です（その部屋の床の縁も列の色で光ります）。最初の数件は、次に手を使う場所が光ります。
- 注文を逃しているなら値上げ、完成品がたまっているなら値下げ、が目安です。
- 5秒ごとと画面を閉じたときに自動で保存します。閉じていた間も最大2時間ぶん進みます（自分の手は動かず、アルバイト・自動仕入れ・注文・支払いが進みます）。閉じていた間の支払いで減る所持金は支払い1回分までで、払いきれないときはアルバイトが休みます。

## 開発の始め方

Node.js 22 以上（24 で確認）が必要です。

```bash
npm ci
npm run dev
```

`http://localhost:5173/pc-tycoon/` を開きます（5173 がふさがっていれば Vite が別の番号を使います）。

### URL のパラメータ（テスト用）

| パラメータ | 意味 |
|---|---|
| `?seed=数字` | 新しく始めるとき・やり直すときの乱数の種を固定する |
| `?speed=倍率` | 時間の進みを速める（`0` で止める） |
| `?debug=1` | テストとスクリーンショット用の窓口 `window.__pct` を出す（ボットで早送り、部品の数を決めるなど） |

## テストの回し方

| コマンド | 内容 |
|---|---|
| `npm test` | Vitest。ルール本体の単体テスト、同じ種で同じ結果、不在の進行と実際の進行の一致、セーブの往復と版1からの変換、Zod の検査、手触りの目安（ボット100回の中央値） |
| `npm run e2e` | Playwright（390×844）。公開用にビルドして、画面の切り替え（タップとスワイプ）、作業で所持金が増える、足りない部品を新品で補う、出品価格、雇う、再読み込み後のセーブ、不在のまとめ、書き出し・読み込み、クリアを確かめる |
| `npm run screens` | 主な画面のスクリーンショットを `docs/screens/` に保存（ラフと同じ 780×1688） |
| `npm run sim` | 手触りの目安をボットで測って表示する |
| `npm run build` | 型の検査と公開用のビルド（`dist/`） |

初めて e2e を回すときは、先に `npx playwright install chromium` でブラウザを入れてください。

## 構成

| フォルダ | 役割 |
|---|---|
| `src/core` | ルール本体（状態・刻み・命令・乱数・ボット・指標）。DOM・PixiJS・React・Zustand・localStorage を使わない Pure TypeScript |
| `src/data` | `balance.json` と Zod のスキーマ（型はスキーマから作る） |
| `src/store` | ルール本体を決まった刻みで回す係（`runtime.ts`）と、画面に見せる写しを持つ Zustand |
| `src/ui` | React の部品と CSS |
| `src/world` | PixiJS の部屋の描画（写実寄りのアイソメトリック。影・明暗・質感・物の描き込み・人と物の動き。文字は描かない） |
| `src/save` | `SaveStore`（今は localStorage。あとで Dexie に差し替えられる形）、版の変換、書き出し・読み込み |
| `tests` | Vitest |
| `e2e` | Playwright |
| `docs` | 仕様・元の数値・ラフ・スクリーンショット・版1の数値の根拠（`sim_stage1.py`） |

更新の頻度は分けています。ルール本体は 0.1秒刻み（タイマー）、PixiJS の部屋は毎フレーム、React の表示は1秒に10回です。

### 数値

`docs/balance.stage1.json` が元の数値（版2）です。`src/data/balance.json` はその写しに、コードに数値を書かないための調整値を足したものです（元の数値と同じであることはテストで確かめています）。

- `bottleneck`：詰まりの判定（生産の秒数の割り方、表示のしきい値、切り替えまでの秒数）
- `display`：表示の頻度、収入を平均する秒数、残りが少ない注文を赤くする秒数、雇った後の予想・実測の秒数、支払いの予告、序盤の導きなど
- `bot`：想定の遊び方（Smart ボット）の判断の数値

版2の数値は、TypeScript のボット（`npm run sim`）で手触りの目安を測って決めました。`docs/sim_stage1.py` は版1の数値の根拠として残しています。

## 公開
